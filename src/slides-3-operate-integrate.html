Operate·Customisation

Bend the model to your estate without forking anything.

Custom fields

Add your own attributes to almost any object: text, integer, boolean, date, URL, JSON, a pick list or a reference to another object. They show in the UI, filters, exports and both APIs.

4.7: selection fields now return both the raw value and its label in REST and GraphQL, for example {"value": "datacenter", "label": "Data Center"}.

customization/custom-fields

Tags and config contexts

Tags label anything for filtering. Config contexts attach JSON data to devices and VMs by site, role, platform, tenant or tag, then merge it, which is how you hold NTP servers or syslog targets once.

4.7 pre-renders and caches the merged result per device and VM.

features/context-data

Make the UI fit

Custom links jump from an object to your other tools. Export templates render data in any text format. Saved filters and dashboards give each team their own starting view.

custom-linksexport-templates

Config templates

Write a Jinja2 template once, attach it to a device or role, and NetBox renders that device's configuration from its own data and merged config context. Rendering is core. Pushing the result to the device is left to your automation.

Operate·REST API

Everything in the UI is on the REST API, with the docs built in.

curl/api/
# List active sites
curl -s -H "Authorization: Bearer $TOKEN" \
     -H "Accept: application/json" \
     "$NETBOX/api/dcim/sites/?status=active&limit=5"

# Create a site
curl -s -X POST \
     -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     "$NETBOX/api/dcim/sites/" \
     --data '{"name": "London 1", "slug": "lon1",
              "status": "active"}'

# Change one field
curl -s -X PATCH \
     -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     "$NETBOX/api/dcim/sites/1/" \
     --data '{"description": "Primary DC"}'

Tokens

Create one on your profile page. The server generates it, you cannot choose it, and you can only see it once, so store it straight away. A token can be read-only or write-enabled.

Bulk writes, 4.7 style

Send a list to a list endpoint to create or update many objects. Append ?background=true to run it as a job. A 202 only means accepted, so check the job's final status.

Explore it

Your instance serves interactive API docs at /api/docs/.

Operate·GraphQL

Ask for exactly the fields you need, across related objects, in one call.

query/graphql/
query {
  device_list(pagination: {offset: 0, limit: 20}) {
    name
    interfaces(filters: {enabled: true}) {
      name
    }
  }
}
curlone-liner
curl -s \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  "$NETBOX/graphql/" \
  --data '{"query": "query {circuit_list(
    filters:{status: STATUS_ACTIVE})
    {cid provider {name}}}"}'

Why use it

REST returns whole objects and makes you follow links. GraphQL returns one tree shaped like your question, which suits dashboards and inventory builds.

Filter the nested bits

Filters work on related objects too, as the enabled-interfaces example shows, and combine with OR and NOT.

Mind the 4.7 changes

Service filters changed shape: ports became flat port lookups and protocol enum members lost their ROLE_ prefix.

source: GraphQL API documentation · enabled by GRAPHQL_ENABLED=true in the netbox-docker env file

When something changes in NetBox, make something else happen.

1Object changesCreated, updated or deleted, in the UI or the API.
2Event rule matchesBy object type, event and an optional condition.
3Queued in RedisThe user's request finishes without waiting.
4Worker runs itThe rqworker picks the event up.
5ActionA webhook, a custom script or a user notification.
conditionjson
{
  "and": [
    {
      "attr": "status.value",
      "value": "active"

}

Example

Tell your monitoring system to start watching a device the moment its status becomes active, and stop when it changes to anything else.

New in 4.7

Conditions can read pre-change and post-change snapshots. Use changed or unchanged to fire only when a specific attribute moved.

Heads up: webhooks have a configurable timeout in 4.7. If you lowered RQ_DEFAULT_TIMEOUT to 60 seconds or less, also set WEBHOOK_DEFAULT_TIMEOUT or NetBox will refuse to start.

Operate·Python inside NetBox

A custom script is a Python class that runs with full access to your data.

scripts/offline_devices.pypython
from dcim.choices import DeviceStatusChoices
from dcim.models import Device
from extras.scripts import Script


class OfflineDevices(Script):
    class Meta(Script.Meta):
        name = "Offline devices"
        description = "Flag devices marked offline"

    def run(self, data, commit):
        offline = Device.objects.filter(
            status=DeviceStatusChoices.STATUS_OFFLINE
        )
        for device in offline:
            self.log_warning(
                f"{device.name} is offline", device
            )
        self.log_success("Check complete")

Where it goes

Drop the file into the scripts volume. In netbox-docker that is netbox-scripts-files, mounted into the container.

Ways to run it

From the UI with generated input forms, from the REST API, or as a reaction to an event rule. From 4.7 the REST route needs a write-enabled token.

What people build

Provisioning wizards, bulk rack builds, consistency reports and data clean-ups, all using the same models NetBox itself uses.

Integrate·The hub pattern

NetBox sits in the middle. Other tools read it, feed it and react to it.

Read from it

Build inventories, render configs and populate dashboards from intended state, over REST or GraphQL.

Feed it

Load what you already know from spreadsheets, a hypervisor, a cloud account or a CMDB, using the API or a script. NetBox stores it. It does not collect it.

React to it

Event rules and webhooks turn a change in NetBox into a ticket, a pipeline run or a chat message.

Integrate·Extending NetBox itself

When configuration is not enough, a plugin adds first-class features.

What a plugin can add

  • New models, with their own pages and API endpoints
  • Navigation entries and extra panels on built-in pages
  • Background jobs, search indexes and GraphQL types

The community ecosystem

Plugins exist for BGP, topology diagrams, inventory tracking and secrets, among much else. Browse GitHub and the plugin directory, then read each plugin's compatibility table.

github topic: netbox-plugin

Using one with netbox-docker

Build a small image on top of the netbox-docker one that installs the plugin, then enable it in configuration/plugins.py. The netbox-docker wiki walks through it.

wiki: using plugins

Before you upgrade to 4.7

4.7 moved nested group models to ltree (the old MPTT base class is kept but deprecated), upgraded django-tables2 to 3.0 (removing RelatedLinkColumn), and changed how email settings are exposed. A plugin that has not declared 4.7 support may fail at startup. Test it on a copy first.

source: v4.7 release notes, Breaking Changes
